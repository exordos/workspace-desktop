# Workspace Desktop Feature

Для поэтапного переноса из Electron используй [маршрут переноса](../../docs/agents/workspace-desktop-feature-port.md) и зафиксируй итог итерации в карточке фичи.

1. **Найди сценарий.** Начни с [каталога функций](../../docs/plans/features/README.md). Если есть подходящая строка, возьми её ID и сверь основание. Зафиксируй ожидаемый результат из требования задачи или согласованного сценария. Если строки нет, опирайся на задачу. При открытых вопросах сверь [границы фичи](#границы-фичи).

   - **Выбери ревизию референса.** Бери SHA из задачи, затем из строки сценария, затем из раздела [«Источники» каталога](../../docs/plans/features/README.md#источники). Читай исходники на выбранном коммите, например через `git -C ../workspace_ui show SHA:путь`. Если для задачи вне каталога нужен референс, укажи SHA, который использовал.
   - **Проверь, что уже реализовано в Desktop.** Сверь локальный `HEAD` и незакоммиченные правки. Пустая отметка в каталоге означает, что подтверждение ещё не записано. Проследи путь от штатной точки входа до наблюдаемого результата. Для экрана проверь, куда ведёт действие пользователя, какую операцию вызывает и где появляется результат. Укажи, какие части уже есть в коде, какие подключены и что подтверждено запуском. Отметка «Код» относится ко всему сценарию строки.

2. **Определи владельца поведения.** Открой [таблицу ответственности](../../docs/plans/workspace-desktop-architecture.md#модули-и-ответственность) и контракты затронутых модулей. Правила, доступ и данные принадлежат `core`. Навигация, состояние экрана и вызовы адаптеров ОС относятся к `desktop`. Если фича затрагивает оба слоя, опиши, что делает `core` и какую команду, состояние или событие использует `desktop`. Если есть фоновая работа, сверь владельца данных и обработку позднего ответа при переключении аккаунта или выходе.
3. **Переиспользуй существующий код.** Проверь, какие операции, модели и компоненты уже решают часть задачи. По возможности расширяй их в модуле-владельце. Если нужен новый общий механизм, зафиксируй в контракте модуля, почему существующего кода недостаточно и за что отвечает новый механизм.
4. **Реализуй сценарий и проверь результат.** Для выбора уровня проверки используй [Workspace Desktop Testing](../workspace-desktop-testing/SKILL.md). Для компонентов и экранов используй [Workspace Desktop UI](../workspace-desktop-ui/SKILL.md). Если нужен актуальный макет, подключи [Workspace Desktop Figma Bridge](../workspace-desktop-figma-bridge/SKILL.md).

## Границы фичи

- **Решай сам, как получить согласованный результат.** Выбирай подходящий существующий код, размещение состояния и уровень проверки. Обрабатывай ошибки и пограничные случаи, которые описаны в задаче или контракте. При необходимости правь соседний модуль в рамках его контракта.
- **Уточняй решения, которые меняют результат или объём задачи.** Сначала сверь задачу, каталог и контракт. Спроси пользователя, если эти источники оставляют несколько вариантов видимого поведения, а выбор влияет на результат. Уточни также, если для работы нужно включить соседний сценарий или изменить действующий контракт. Сформулируй вопрос через варианты и их последствия для пользователя.
- **Пока ждёшь ответа, продолжай независимую работу.** Изучи текущий маршрут, найди код для переиспользования и реализуй согласованные части. К части, которая зависит от выбора пользователя, переходи после ответа.

Например, для открытия существующего личного чата из списка подключи загрузку последних сообщений и обработай поздний ответ по контракту. Если для клика по каналу ещё не определено, открыть последнюю тему или список тем, уточни этот выбор. Переход к личному чату можно делать дальше, если он входит в задачу.
