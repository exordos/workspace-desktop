# Макеты Workspace через Figma Bridge

Используй `mcp__figma_bridge__*` как основной путь к макету Workspace. Официальный Figma MCP используй по явной просьбе пользователя.

1. Вызови `list_files`. Возьми `fileKey` нужного файла из ответа и передавай его в последующие вызовы. Если Bridge отвечает пустым списком или нужного файла нет, попроси открыть его в Figma и запустить в нём плагин Figma Bridge. Если инструменты недоступны или вызов падает, сообщи конкретную ошибку. Продолжай работу, для которой хватает доступных референсов. После подключения снова вызови `list_files` перед чтением макета.
2. Если пользователь ссылается на выделение, используй `get_selection`. Если дан Figma URL, сопоставь ключ файла с подключённым и возьми `node-id` из ссылки (`123-456` → `123:456` для Bridge). Для поиска по названию возьми страницы через `get_metadata` и уточни узел по [ориентирам макета](references/desktop-anchors.md). Спрашивай о целевом фрейме, если контекста и открытых файлов недостаточно.
3. Читай самый маленький нужный узел через `get_node` и сверяй внешний вид через `get_screenshot`. Для сложной компоновки пригодится `get_layout_tree`, для токенов — `get_variable_defs` и `get_styles`. Проверь родительский фрейм, если важны размещение или состояние соседей. Для спорного взаимодействия сопоставь состояния до и после действия. Отмечай, что измерено по слоям, а что выведено из скриншота или соседнего состояния.
4. Для переноса в код следуй [навыку Workspace Desktop UI](../workspace-desktop-ui/SKILL.md). Если используешь `get_design_context`, предварительно загрузи навык `figma:figma-design-to-code`. При сверке сообщи, какой фрейм и вариант использовал. Меняй Figma только по запросу на правку самого макета.
