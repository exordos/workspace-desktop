# UI Workspace Desktop

Границы модулей описаны в [архитектуре](../../docs/plans/workspace-desktop-architecture.md). Требования к общим компонентам собраны в [плане UI-кита](../../docs/plans/modules/ui-kit.md).

## Референс

- Для переноса существующего компонента начни с каталога `../workspace_ui/docs/COMPONENT_CATALOG.md` относительно корня desktop-проекта. Сверь Storybook, исходник из `packages/web/src/shared/ui/` и место использования. Storybook показывает варианты, текущие вызовы уточняют контракт и реально нужные состояния.
- Если нужен актуальный макет, используй [Workspace Desktop Figma Bridge](../workspace-desktop-figma-bridge/SKILL.md), даже если Figma не упомянута. Для примитива сравни вариант в UI-ките и его экземпляр на экране. Для композиции возьми готовый desktop-экран с тем же сценарием и смежные состояния. Если источники расходятся, опирайся на явные требования пользователя и согласованный референс. Уточняй расхождения, которые меняют результат.
- При запросе на принципы, план или ревью ограничься запрошенным результатом. Реализацию начинай, когда она входит в задачу.

## Реализация

- Переиспользуй готовые компоненты, семантические цвета, типографику, размеры и отступы. Компонент отвечает за оформление и локальные взаимодействия, получает доступность действия извне и сообщает о действии. Экран связывает действия с командами. `workspace-core` владеет бизнес-правилами, правами, данными и синхронизацией.
- **Прототип и перенос на GPUI.** Сверяй задачу с [планом перехода](../../docs/plans/workspace-desktop-roadmap.md#предлагаемый-переход-на-gpui) и API зафиксированной версии GPUI. Для проверки списка достаточно отдельного окна с тестовой историей и редактором. При переносе рабочего чата оболочка владеет аккаунтом и маршрутом, экран разговора — историей и прокруткой. Редактор может быть отдельной `Entity`, хранить состояние ввода и передавать намерение отправки экрану через типизированное событие.

## Проверка

- Для композиции проверь компонент в контексте экрана, если он уже есть. Для прототипа GPUI используй сценарий в его окне и [правила проверки UI](../workspace-desktop-testing/SKILL.md#проверка-ui).
- Сравни нативное окно и референс при одинаковых размере, теме и состоянии. Проверь затронутые состояния, включая фокус и клавиатуру, длинный текст, наведение и недоступность там, где они применимы. Отмечай фактические расхождения и проверки, которые не удалось провести.
- Запусти применимые проверки из [AGENTS.md](../../AGENTS.md).
