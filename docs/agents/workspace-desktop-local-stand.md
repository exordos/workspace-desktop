# Локальный стенд Workspace Desktop

`cargo stand` запускает настоящий Workspace Messenger на `https://127.0.0.1:21443` и показывает SHA бэкенда. Нужен запущенный Docker Desktop или Docker Engine с Compose. Установка Docker выполняется отдельно. Первый запуск скачивает [workspace_backend](https://github.com/exordos/workspace_backend), собирает его с зависимостями из `uv.lock` и собирает [MinIO Community](https://github.com/minio/minio/tree/9e49d5e7a648f00e26f2246f4dc28e6b07f8c84a) из закреплённого коммита. Это может занять несколько минут.

Стенд общий для всех worktree. Кэш бэкенда, конфигурация, пароли и локальный сертификат лежат в `${XDG_DATA_HOME:-~/.local/share}/workspace-desktop/stand`. PostgreSQL и MinIO используют постоянные Docker-тома. Тестовый IAM выдаёт подписанные токены для `stand-a` и `stand-b`. У аккаунтов и проекта фиксированные UUID, а пароли генерируются при первом запуске. Мессенджер проверяет токены штатным IAM-драйвером.

## Подключить Desktop

Из нужного worktree запусти:

```sh
cargo stand
(
    stand_env=$(cargo stand env A) &&
    eval "$stand_env" &&
    cargo dev --test-profile
)
```

Для второго аккаунта передай `B` вместо `A`. Команда `env` передаёт пароль и путь к тестовому CA, поэтому её вывод лучше сразу подставлять в окружение. Скобки ограничивают действие переменных тестовым запуском. Рабочий чат обоих аккаунтов появится в списке личных чатов.

## Жизненный цикл

- `cargo stand` переиспользует готовый стенд после проверки HTTPS, REST и WebSocket. При запуске остановленного стенда сверяет `origin/master` и переиспользует образ, если ревизия и рецепт сборки совпадают.
- `cargo stand restart` перезапускает сервисы на текущей ревизии. Учётные записи, сообщения и файлы сохраняются.
- `cargo stand update` скачивает актуальный бэкенд, при необходимости пересобирает стенд и применяет миграции. Запускай, когда остальные прогоны завершены.
- `cargo stand stop` останавливает сервисы.

Команда `bash tests/workspace-stand.sh /путь/ко/второму/worktree` отправляет тестовое фото от A через API, перезапускает стенд, затем под B читает сообщение и сверяет байты файла из второго worktree. Это перезапускает общий стенд. Для ручной проверки открой личку с A в Desktop под B и нажми на фото `stand-probe.png`.
