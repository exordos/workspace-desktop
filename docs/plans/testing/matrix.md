Снимок на 25 ноября 2026 года: начальная инвентаризация текущего рабочего дерева. Каталог функций задаёт состав и постоянные ID; матрица помогает выбрать следующую работу. Строки с основанием «Уточнить» в каталоге — кандидаты или открытые вопросы, а не автоматически утверждённый объём. Пустая отметка «Код» в каталоге означает отсутствие записанного подтверждения, а не доказанное отсутствие реализации.

## Как читать и обновлять

- **Не сверено** — нет достаточной сверки; это не означает, что теста или реализации нет. **Частично** — указанная проверка покрывает лишь перечисленную часть. **Не запускали** — существование теста установлено, результата для этого снимка нет. **Прошёл** — указан конкретный прогон и его границы. **Не подтверждён** — требуемый прогон не выполнен или его результат неизвестен. **Отложено** — сознательно вне текущего среза, не оценка качества функции.
- Кейс, готовность функции и результат прогона — разные сведения. Тест может существовать для незавершённой функции, а пройденный mock не подтверждает реальный сервер или другие варианты кейса. Не ставить общий зелёный статус модулю по одному тесту. При неясном требовании записать вопрос и не подменять ожидаемое поведение текущим кодом.
- Перед правкой открыть ссылку на функцию и кейс, проверить актуальные код и незакоммиченные изменения. После работы указать конкретный тест, среду, команду, дату и проверенную ревизию или явно указать рабочее дерево с незакоммиченными изменениями; отдельно записать непройденные шаги и причину. Менять статус только на основании проверки её содержимого и фактического результата.
- Использовать существующие кейсы и ссылки на них: одна пользовательская цепочка может относиться к нескольким функциям. Системные действия пока отложены по решению пользователя. Разделы и фичи вне первого среза сохраняются в матрице, но не считаются проверенными.

## Очередь работы

1. Запустить общий сценарий на выделенном локальном бэкенде, записать результат и устранить подтверждённые расхождения. Отдельно проверить получение сообщения уже подключённым B и обновление списка чатов.
2. Расписать и автоматизировать вложение A → B: подготовка, загрузка, сообщение, просмотр/скачивание и проверка байтов в обеих средах. Сверить существующий GPUI-тест с COM-08.
3. Раскрыть историю, навигацию, черновики и сбои: сопоставить существующие тесты с каждым ожидаемым результатом, затем добавить недостающее. Не выдавать частичные проверки за завершённый кейс.
4. Продолжить по 23 областям каталога: добавлять строки по ID функций и кейсов по мере сверки. Кандидаты с неясными требованиями сначала уточнять; системные сценарии оставлять отложенными до отдельного решения.
