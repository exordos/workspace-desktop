# Базовый замер фоновых сообщений

Родительский документ — [фоновая обработка и замеры](../workspace-desktop-architecture.md#фоновая-обработка-и-замеры). Это исследование SYNC-011, а не порог производительности.

## Воспроизведение

На исходном `main` 27548aa56889cc140a59d2addd3dc3b8e741925c с добавленным сценарием `crates/workspace-core/tests/support/background_baseline.rs` использованы macOS 27.0.1 (26A434), arm64, rustc 1.100.0 и cargo 1.100.0. Сборка debug, без других флагов Cargo. Для каждого запуска тест создаёт новую временную SQLite и два аккаунта в памяти; при завершении временный каталог удаляется.

```sh
cargo test -p workspace-core --test auth_lifecycle --no-run --message-format=json > /tmp/workspace-baseline-build.jsonl
TEST_BIN=$(python3 -c 'import json; print(next(x["executable"] for x in map(json.loads, open("/tmp/workspace-baseline-build.jsonl")) if x.get("reason") == "compiler-artifact" and x.get("target", {}).get("name") == "auth_lifecycle" and x.get("executable")))')
/usr/bin/time -l "$TEST_BIN" --ignored --exact background_baseline::background_messenger_baseline --nocapture
/usr/bin/time -l "$TEST_BIN" --ignored --exact background_baseline::background_messenger_baseline --nocapture
```

Две фоновые задачи Runtime получают по 1000 одинаковых по форме входящих личных сообщений с UUID, адресом стрима и темы, автором и временем. Сообщения чередуются между аккаунтами; следующее отправляется после подтверждения курсора предыдущего. Каждый запуск проверяет по 1000 строк и курсор 1000 для каждого владельца. Нагрузка включает все обработчики, которые выполняются для этого типа события: запись сообщения, истории, цели уведомления и курсора. Отдельные события счётчиков, REST, WebSocket, отображение и системные уведомления в неё не входят.

Задержка — от начала отправки в тестовый канал до наблюдения сохранённого курсора через повторные запросы SQLite; она включает ожидание очереди, работу Runtime, транзакцию и опрос. Это последовательная нагрузка, не предел пропускной способности. `/usr/bin/time -l` измеряет весь процесс теста, включая подготовку, опрос и завершение; CPU — сумма user и sys, RSS — максимальный размер resident set в байтах. Нагрузка машины, debug-сборка и сам опрос влияют на результат.

Для сравнения отдельных обработчиков понадобятся явные конфигурации с одинаковым потоком, начальной базой, окружением и способом замера, а также восстановление данных перед повторным включением обработчика. Отдельно нужны замеры физической записи и времени открытия чата. Эти цифры не характеризуют сетевой путь и не задают требования к продукту.
