# Источник индикатора непрочитанного в Dock

Исследование NTF-006. Референс Workspace UI: `af0999886daaffefc2a7be33f8dcf3f484a0e9c1`; сервер: `bc986e07981737f57eeb5b205a5bee25c42e8858`. Это анализ исходников, а не проверка работающего сервера или Dock.

## Что показывает референс

В [layout.ui.tsx](https://github.com/exordos/workspace_ui/blob/af0999886daaffefc2a7be33f8dcf3f484a0e9c1/packages/web/src/widgets/layout/layout.ui.tsx#L85-L88) число непрочитанных личных сообщений задано равным нулю. Число упоминаний берётся только для текущего владельца; несовпадение владельца и неизвестное значение дают ноль ([вызов](https://github.com/exordos/workspace_ui/blob/af0999886daaffefc2a7be33f8dcf3f484a0e9c1/packages/web/src/widgets/layout/layout.ui.tsx#L146-L171)). [Хук](https://github.com/exordos/workspace_ui/blob/af0999886daaffefc2a7be33f8dcf3f484a0e9c1/packages/web/src/widgets/layout/layout-app-icon-badge.hook.ts) передаёт 1, если хотя бы одно из двух чисел больше нуля, иначе 0. На macOS [Electron](https://github.com/exordos/workspace_ui/blob/af0999886daaffefc2a7be33f8dcf3f484a0e9c1/packages/electron/src/main.ts#L657-L682) меняет иконку на вариант с точкой, а не показывает число; во время звонка этот путь не обновляет иконку.

Упоминания загружаются всеми страницами `GET /api/workspace/v1/messenger/messages/?mentioned=true&read=false`, с контекстом проекта и сортировкой по времени ([запрос](https://github.com/exordos/workspace_ui/blob/af0999886daaffefc2a7be33f8dcf3f484a0e9c1/packages/web/src/entities/activity/activity-mentions.api.ts#L102-L135), [клиент](https://github.com/exordos/workspace_ui/blob/af0999886daaffefc2a7be33f8dcf3f484a0e9c1/packages/web/src/shared/api/messenger-client.ts#L202-L225)). Сервер хранит признаки упоминания и непрочитанного отдельно по проекту и пользователю ([флаги](https://github.com/exordos/workspace_backend/blob/bc986e07981737f57eeb5b205a5bee25c42e8858/workspace/messenger_api/message_flags.py)); события сообщений содержат `read` и `mentioned` для получателя ([формирование](https://github.com/exordos/workspace_backend/blob/bc986e07981737f57eeb5b205a5bee25c42e8858/workspace/messenger_api/events.py#L570-L605)).

[Обработчик событий](https://github.com/exordos/workspace_ui/blob/af0999886daaffefc2a7be33f8dcf3f484a0e9c1/packages/web/src/entities/activity/activity-realtime-applier.lib.ts) применяет изменения только активного владельца: добавляет непрочитанное упоминание, удаляет прочитанное или удалённое, очищает тему и стрим при чтении или удалении. Во время загрузки изменения буферизуются, после переподключения индекс запрашивается заново. [Модель](https://github.com/exordos/workspace_ui/blob/af0999886daaffefc2a7be33f8dcf3f484a0e9c1/packages/web/src/entities/activity/activity.model.ts#L272-L389) проверяет владельца, поколение и токен загрузки.

Счётчик Desktop из `messenger/rest.rs::unread_snapshot` относится к системной папке «Все чаты». Он не различает упоминания и личные сообщения, поэтому его нельзя считать подтверждённым источником точки референса.

## Проверяемые состояния референса

| Ситуация | Происхождение и обновление точки |
| --- | --- |
| Запуск | До полного ответа индекс неизвестен и трактуется как ноль. После загрузки всех страниц точка включается при непустом индексе. |
| Смена аккаунта | Старый индекс не совпадает с текущим владельцем и не используется; новый запрос привязан к владельцу и поколению. Точка обновляется после получения нового индекса. |
| Прочитано последнее упоминание | Событие чтения удаляет подходящие записи индекса; при нуле точка снимается. Точный набор определяется типом события и границей сообщения. |
| Отзыв доступа | `stream.deleted` очищает записи соответствующего стрима; точка снимается, только если других упоминаний не осталось. |
| Ошибка источника | Повторы через 1 и 3 секунды; после исчерпания значение неизвестно и трактуется как ноль. При повторной загрузке индекс также очищается, поэтому точка может временно исчезнуть. |

Поведение выше описывает активный контекст в референсе; оно не доказывает, что такой выбор подходит для фоновых аккаунтов Desktop.

## Вопрос для решения перед реализацией

Должен ли Dock учитывать только выбранный аккаунт, как закреплённый референс, или объединять упоминания всех активных и фоновых аккаунтов? Отдельно нужно подтвердить, следует ли воспроизводить текущее обнуление личных сообщений и скрытие точки при ошибке источника. До ответа не подменять эти правила общим счётчиком «Все чаты». После решения минимальный срез: индекс упоминаний выбранных по политике контекстов, согласование страниц с событиями и адаптер точки Dock; тестировать смену поколения, отзыв доступа, чтение и ошибки на изолированном источнике.
