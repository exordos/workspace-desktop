## Что нужно от API

Пути относительно `/api/workspace/v1`. Основа — контракт backend `3.4.2` и ранее проверенный доступ к коллекциям на тестовом стенде. [OpenAPI](https://github.com/exordos/workspace_backend/blob/3.4.2/docs/public_workspace_api.yaml)

| № | Что можно подключить | Что уточнить с бэкендом или продуктом |
| --- | --- | --- |
| 01 | `GET /external_accounts/`, `GET /mail/folders/`, `unread_count`. «Избранное» можно построить по `starred=true`, «Черновики» — через `GET /mail/drafts/`. | Смысл счётчика группы ящика и свёрнутых групп. На макете в одной группе две строки «Корзина». Уточнить отображение специальных и пользовательских папок. |
| 02 | `GET /mail/messages/` с `folder_uuid`, `external_account_uuid`, `read=false` и фильтрами по полям. | Область поиска, какие поля искать и какие опции должны быть под иконкой фильтра. Полнотекстовый поиск по почте требует серверного контракта, если он входит в сценарий. |
| 03 | Коллекция писем возвращает UUID, тему, адреса, текст или HTML, отметки и даты. Есть курсорная пагинация. Группы по дате и короткое превью формирует клиент. | Источник отображаемого имени автора, порядок по времени получения или отправки. В модели есть `from_address`, `created_at`, `sent_at`. Список по умолчанию сортируется по `created_at`. |
| 04 | Одиночные `read` / `unread`, `star` / `unstar`, `move`, `trash` / `restore`. Для архива и спама возможен `move` в папку того же ящика. Действия над импортированным письмом меняют копию в Workspace. | Правила массовых операций, результат частичного успеха и область «выбрать все». Счётчик выбранных нарисован и на основном списке. Уточнить момент его появления. Для жалобы, реакции и массовой пересылки нужен отдельный контракт, если эти кнопки остаются. |
| 05 | Чтение отдельного письма по UUID и одиночные действия. Черновик ответа принимает `reply_to_uuid` и адреса To/Cc/Bcc. | Для цепочки нужны стабильный ID или связи импортированных писем. Текущий импорт связи ответов не сохраняет, отправка SMTP не выставляет `In-Reply-To` и `References`. Пересылка требует согласовать формирование тела и вложений, обычное письмо можно отправить через существующий черновик. |
| 06 | Файловый API Workspace с ACL владельца, `attachment_urns` и скачивание по UUID файла. | Превью и обработка встроенных изображений в HTML. Проверить реальные письма с обычным вложением и отдельно с изображением внутри текста. |
| 07 | CRUD через `/mail/drafts/`, текст и HTML в `payload.parts`, отправка через `/mail/drafts/{uuid}/actions/send/invoke`. Привязка отправителя идёт по ящику черновика. Отправка требует активного внешнего аккаунта, получателя и непустого тела. | Состояния `queued`, `sent`, `failed` доступны, причина ошибки доставки письма пока скрыта. По иконкам редактора уточнить отложенную отправку, Диск, календарь и подпись. Обычная ссылка или форматирование могут сохраняться внутри тела. |
| 08 | Черновик принимает списки почтовых адресов. Общий `GET /users/` может дать адреса пользователей Workspace, для внешнего адреса доступен ручной ввод. | Источник подсказок по имени и никнейму, поиск адресной книги внешнего ящика и правила выбора отправителя при смене ящика. |
| 09 | Mail API отдаёт тело и ссылки на файлы. Calendar API хранит личные разовые события. | Нужен контракт приглашения. Уточнить распознавание входящего приглашения, устойчивый ID, обновление или отмену, действия RSVP и доставку ответа организатору. |

## Первый кандидат для нативной почты

1. Собрать на фиксированных данных 01, 02 с фильтром «Непрочитанные», 03 и 05 с одним письмом. В галерее проверить геометрию, клавиатуру и длинные данные.
2. Подключить чтение в `core::mail` штатным токеном проекта. Маршрут пользователя — «Почта» → ящик → папка → письмо → обратно. Через GPUI loopback проверить пагинацию, отказ сервера и смену аккаунта A → B во время запроса. На выделенном стенде открыть известное тестовое письмо.
3. После этого подключить одиночные действия, вложения и черновик с обычной отправкой. На стенде проверить изменение состояния письма после ответа API и доставку тестового письма. Поиск, массовые операции, цепочки и RSVP имеют отдельные вопросы в таблице выше.
