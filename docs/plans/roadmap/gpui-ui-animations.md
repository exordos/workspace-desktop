# Анимации интерфейса Workspace Desktop

[UI-кит](../modules/ui-kit.md) · [Скилл работы с анимациями](../../../skills/workspace-desktop-animation/SKILL.md)

## Цель

Один переключатель «Анимации интерфейса» во «Внешнем виде» управляет эффектами Workspace Desktop. Настройка действует на все аккаунты в локальном профиле и сохраняется после перезапуска. Для нового и ранее сохранённого профиля анимации по умолчанию включены.

При выключении пользователь видит то же функциональное состояние сразу. Например, панель открывается на своём месте, а индикатор загрузки сохраняет статичную подпись. Если эффект уже проигрывается, следующий рендер завершает его и прекращает запросы его кадров. Включение действует на следующие переходы. Циклический эффект может возобновиться, пока актуально его состояние, например пока продолжается загрузка.

## Общий механизм

| Владелец | Ответственность |
| --- | --- |
| Хранилище настроек Desktop | Читает общий флаг локального профиля. Публикует новое значение после успешного сохранения. Окно обновляется при переключении настройки. |
| UI-кит GPUI | Общий помощник принимает стабильный ключ, способ запуска и функцию отрисовки эффекта. Для обычного перехода использует `with_animation`, а при выключенном флаге сразу строит итоговый кадр. Создаёт `Animation` только после проверки флага. |
| Компонент | Задаёт длительность, кривую, начальное и конечное состояния. Связывает прогресс с шириной, прозрачностью, положением или их сочетанием. Для цикла задаёт статичное представление, для обратимого перехода хранит текущее положение. |

Настройка читается из памяти. Для списка или другого контейнера с повторяющимися элементами можно прочитать её при отрисовке родителя и передать значение вниз. Каждому эффекту достаточно общей точки запуска. Ручной переход, который вызывает `request_animation_frame`, использует ту же проверку и прекращает запросы кадров при выключении.

По умолчанию все эффекты интерфейса подчиняются переключателю. Для отдельного эффекта можно явно объявить исключение, если без него теряется важный смысл взаимодействия. Причину фиксируем рядом с эффектом и проверяем в выключенном режиме. Первый этап запускаем с пустым списком исключений.

Общая настройка относится к эффектам интерфейса GPUI. Воспроизведением медиа и системными эффектами macOS управляют их владельцы. Обновления интерфейса, данные и фокус работают в обоих режимах.

Сейчас в коде есть пульсация при фоновой загрузке истории через `with_animation` и раскрытие баннера разрешений через `request_animation_frame`. Они покрывают декларативный и ручной пути. ## Этапы

| Этап | Результат | Как принять |
| --- | --- | --- |
| 1. Настройка и общий механизм | Сохранение флага, переключатель во «Внешнем виде» и API UI-кита для обоих путей запуска. | Старый профиль сохраняет текущее поведение. Значение переживает перезапуск и смену аккаунта. При ошибке записи остаётся прежнее значение. |
| 2. Существующие эффекты | Подключить пульсацию истории и раскрытие баннера. | Выключение во время пульсации оставляет статичный индикатор. Баннер сразу доходит до нового положения, сохраняет кнопки и фокус. После завершения отключённый эффект не запрашивает кадры. |
| 3. Новые эффекты по одному | Выбирать компонент отдельной задачей. Кандидаты — появление быстрых реакций и заполнение полос результатов опроса. | Проверить оба режима, повторное действие до завершения и влияние на геометрию, фокус или прокрутку там, где они меняются. |

При оценке производительности сравниваем одинаковое действие в обоих режимах на одном наборе данных. Для начала проверяем запросы кадров от самого эффекта. Замеры времени кадра и активности CPU полезны перед распространением подхода на длинные списки или при заметном ухудшении. Оценку энергопотребления делаем по измерениям.

**Точка продолжения.** Реализовать этап 1 и подключить существующие эффекты из этапа 2. Новые эффекты добавлять после проверки общего переключателя.
