# Единый рендеринг Markdown в истории

## Результат и референс

Сообщения показывают Markdown и элементы Workspace в исходном порядке. Текст рядом с несколькими зашифрованными фрагментами остаётся читаемым при изменении ширины окна; фрагменты сохраняют независимые состояния доступа и раскрытия.

Референс Workspace UI — `af0999886daaffefc2a7be33f8dcf3f484a0e9c1`: Markdown разбирается через `marked`, специальные ссылки заменяются компонентами в потоке сообщения. В Desktop используется GPUI, поэтому способ размещения интерактивных элементов нужно проверить на его фактическом API.

## Границы и владельцы

- Core владеет проверкой ссылок, шифрованием, правами доступа и разбором служебных адресов; используется существующий Rust-парсер `markdown`.
- Desktop отвечает за представление Markdown, геометрию, взаимодействие и состояние раскрытия. При работе с защищённым текстом сохраняется существующий контракт отзыва доступа.
- База итерации — Desktop `12126fbb904e2ee1407438737dcdcc477a83ef31`. Существующие маршруты сообщений, цитат, вложений и защищённого текста нельзя считать объединёнными до проверки фактического подключения.

## План реализации

| Срез | Результат |
| --- | --- |
| Модель и разбор | Общий разбор Markdown с сохранением исходных диапазонов и распознаванием элементов Workspace; буквальный код не превращается в интерактивный элемент. |
| Отображение | Текстовые фрагменты сохраняют порядок, форматирование и переносы; слова получают измеренную ширину и не схлопываются при раскладке рядом с кнопками фрагментов. Ссылки и защищённые фрагменты сохраняют свои действия. |
| Интеграция | Обычные и защищённые сценарии подключаются без потери выбора текста, переходов, ключей и отзыва доступа; неподключённые случаи явно перечисляются. |
| Проверки | GPUI-сценарии с несколькими фрагментами, текстом и форматированием на разных ширинах, действиями и изменением размера; регрессии соседних ссылок и цитат. |

## Точка продолжения

Сценарий относится к `MSG-HIST-011`. Разбор Markdown и защищённый путь используют общие исходные диапазоны; выделение не пересекает закрытые фрагменты. GPUI 0.2.2 не умеет вставлять произвольную кнопку внутрь `StyledText`, поэтому смешанное тело пока собирается flex-потоком. Ширина каждого текста измеряется GPUI до flex-раскладки, а максимум ограничен шириной бабла; это предотвращает сжатие слов до нуля.

Проверены шесть тестов модели Markdown и GPUI-тест геометрии двух секретных фрагментов: проверяются ширины и высоты текстовых фрагментов и ссылки при обычной и узкой ширине, включая изменение размера окна. `cargo check-architecture` прошёл. Loopback-тесты требуют локального TCP bind, запрещённого средой (`PermissionDenied`). `cargo dev` собрал приложение, но тестовый вход не открыл окно: IAM тестового Workspace вернул временную ошибку. `cargo fmt --all -- --check` находит существующие расхождения форматирования в других файлах workspace. Полная матрица Markdown не выполнялась.
