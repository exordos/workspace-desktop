# Карточка ссылки на звонок в истории Desktop

[CALL-005](../../features/sections/calls.md#call-005) · [План звонков](../sections.md) · [Контракт мессенджера](../../modules/messenger.md)

## Результат итерации

Обычное Markdown-сообщение с разрешённой ссылкой Jitsi отображается карточкой шириной 353 px, как в макете. При нехватке места ширина ограничивается 88% строки; длинное имя комнаты сокращается в одну строку, а локация показывается отдельно и переносится по словам. Нижний скруглённый угол зеркально зависит от стороны сообщения. Наведение на подтверждённую карточку показывает `pointer`, а нажатие открывает ссылку в системном браузере. Desktop не подключает и не встраивает Jitsi.

## Референс и решения

- Electron `workspace_ui@af0999886daaffefc2a7be33f8dcf3f484a0e9c1`: [распознавание Jitsi-ссылок](../../../../../workspace_ui/packages/web/src/shared/lib/jitsi.ts) и [карточка в истории](../../../../../workspace_ui/packages/web/src/widgets/workspace-message-list/workspace-message-bubble-jitsi-card.ui.tsx).
- Макет — [Exordos Core (Copy), узел `2473:6985`](https://www.figma.com/design/VmfwiIV4fW8gHfU3AhCZGZ/Exordos-Core--Copy-?node-id=2473-6985). Измеренный кадр — 353×76 px, тёмно-зелёная подложка, подпись звонка, имя комнаты, локация темы, значок телефона и время сообщения.
- Локацию темы показываем с `#` по макету. Electron передаёт в карточку имя темы без префикса.
- По решению пользователя не показываем аватары участников. Нижнюю подпись `0:47` убираем: Desktop не получает длительность звонка из истории.
- Имя комнаты берём из сегмента ссылки. Локацию — из текущего разговора: собеседник в личке, `# тема` в теме канала или название канала. Время и статус доставки — из метаданных сообщения.

## Границы и контракты

- Core проверяет HTTPS-ссылку и разрешённый сервер конференций либо публичный `meet.jit.si`.
- Desktop распознаёт ссылку только в обычном Markdown-теле, показывает карточку и повторно сверяет UUID и тело сообщения перед открытием.
- Пользователь сам открывает ссылку; системный адаптер передаёт её браузеру ОС.
- Входящие вызовы, список участников, длительность, отдельное окно и управление медиа остаются за пределами этого среза.
- База Desktop — текущая `main`; источники поведения взяты из `workspace_ui@af0999886daaffefc2a7be33f8dcf3f484a0e9c1`.

## План проверки

| Уровень | Действие или сбой | Ожидаемый результат |
| --- | --- | --- |
| GPUI | Открыть подтверждённое сообщение со ссылкой Workspace Jitsi или `meet.jit.si` | Видны имя комнаты, собеседник или локация темы/канала, время; карточка открывает ссылку в браузере. Участники и длительность не показываются. |
| GPUI | Сравнить входящую и исходящую карточки, затем навести курсор на подтверждённую | Нижний угол зеркально совпадает со стороной сообщения; над всей карточкой отображается `pointer`. |
| GPUI | Сравнить короткое и длинное содержимое карточки при широкой и узкой строке | Карточка занимает 353 px, пока есть место, и сжимается до 88% ширины строки; топик переносится, длинная комната остаётся в одну строку. |
| GPUI | Открыть Markdown с произвольным HTTPS-адресом, чужим хостом или некорректной комнатой | Текст сохраняет обычное оформление, переход по нему следует существующему поведению ссылок. |
| История | Изменить или удалить исходное сообщение до нажатия | Карточка не открывает прежний адрес. |

## Точка продолжения

- Реализовано в текущей `main`: Core распознаёт разрешённый URL и повторно сверяет владельца, поколение, размещение и ревизию сообщения перед открытием. История Desktop рисует карточку с локализованным названием комнаты, контекстом разговора, временем и статусом доставки. Аватары и длительность не показываются.
