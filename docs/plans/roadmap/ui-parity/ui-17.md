# UI-17. Проверки выпуска и обновления GPUI

База — принятая UI-12, `fafcd6329bfc53a53b610dbb1a723c971f5a3f0e`, GPUI `0.2.2`. [Карточка и критерии](../gpui-ui-parity.md#ui-17-проверки-для-выпуска-и-обновления-gpui) · [Приёмка UI-12](../gpui-ui-parity-acceptance.md).

## Границы и файлы

1. Закрепить команду короткого прогона `sh scripts/check-workspace-desktop-ui.sh <новый-каталог-результатов>`. Использовать существующие GPUI-тесты и локальные HTTPS/WSS-фикстуры. В script оставить вызовы Cargo, проверку состава выбранных тестов и пути к журналам. Взять схему запуска с сохранением кода возврата из `21/checks.sh` рядом с журналом миграции. Пути и SHA из разового скрипта не переносить.
2. Добавить инструкцию выпуска и обновления в `docs/plans/roadmap/gpui-ui-parity-release.md` со ссылками на сценарии, команды и ожидаемые результаты. Добавить ссылку из UI-17 в `docs/plans/roadmap/gpui-ui-parity.md`. Для `.app` переиспользовать `scripts/bundle-workspace-desktop-macos.sh`, для диагностики — `gpui_chat_probe`, для необязательного контрольного кадра — `ui_scene`.
3. Владелец UI-17 правит перечисленные script и документы. Файлы клиента, ядра, фич и зависимостей меняет их владелец при подтверждённой регрессии. Подготовка и проверка сценариев UI-17 идут параллельно с UI-13–16 и UI-18. Сценарии на реальном окне идут последовательно, итоговый выпуск проверяется на интегрированном SHA.

## Короткий автоматический прогон

Все тесты ниже зарегистрированы в `cargo test --locked -p workspace-desktop --features gpui-test --lib`. На `fafcd63` они записаны в `ui-13-18/baseline/gpui.log` рядом с журналом миграции.

| Сбой | Существующий фильтр теста и ожидаемый результат |
| --- | --- |
| Теряется фокус основного маршрута или исходящее теряется/дублируется | `catalog_click_and_submission_reach_https_queue`: Tab от шапки до истории и редактора и обратно, запись через HTTPS/SQLite, подтверждение и пустая очередь, повтор после отказа сохраняет ввод. |
| Открывается или получает исходящее тема по умолчанию, нарушены права | `explicit_topic_accepts_mouse_and_keyboard_in_each_account` и `explicit_topic_is_rechecked_before_queue_and_before_post`: точная тема A/B, один POST и подтверждение, закрытая или чужая тема и шифрованная цель отсекаются на соответствующем шаге. |
| Запоздавшая история заменяет экран или WSS не восстанавливается | `late_history_keeps_the_reopened_account_conversation` и `local_wss_recovers_pruned_cursor_and_changed_epoch`: маршрут сохраняется, локальный курсор и снимок восстанавливаются после обрыва и смены эпохи. |
| Клавиши истории или редактора перестают работать | `history_keys_scroll_and_load_older_page` и `editor_keyboard_and_ime_share_the_same_send_path`: прокрутка, догрузка, сохранение пути Enter, вставка и композиция IME. |
| Цель уведомления теряет аккаунт или меняет окно | `notification_click_reaches_its_account_and_message_in_the_same_window`: синтетический клик находит B и сообщение и применяет переход в существующем окне. |
| Работа продолжается после выхода либо профиль остаётся заблокирован | `shutdown_waits_for_started_work_and_releases_profile`: исполнитель ожидает начатую работу, затем освобождает профиль. |

Команда использует чистый checkout с собственным `CARGO_TARGET_DIR` и `CARGO_BUILD_BUILD_DIR`, одинаковыми в пределах прогона. Записывает SHA, `rustc --version`, `cargo --version`, `sw_vers`, архитектуру и вывод `cargo tree --locked -p workspace-desktop -i gpui`. При отсутствии Cargo-кэша использует обычный `--locked`. `--offline` пригоден при подготовленных зависимостях. На неподдерживаемой ОС команда сообщает, что для набора GPUI требуется macOS, и возвращает ошибку.

Перед фильтрованным прогоном вызвать `cargo test --locked -p workspace-desktop --features gpui-test --lib -- --list` один раз. У каждого выбранного имени должно быть одно полное совпадение в списке и результат `ok` в выводе теста. Это ловит переименование, игнорированный тест и запуск с неверными feature, когда libtest может успешно выполнить 0 тестов. Каждый прогон сохраняет полный stdout/stderr и статус в отдельном журнале. При падении выводит имя случая и путь к журналу. Прогон с одним именем воспроизводится так:

```sh
cargo test --locked -p workspace-desktop --features gpui-test --lib \
  catalog_click_and_submission_reach_https_queue -- --nocapture
```

Проверить `sh -n`, выполнить команду из чистого worktree с каталогом вывода, содержащим пробел, и повторить в новом каталоге. Для проверки отказов использовать временную копию script и подставной `cargo` через `PATH`. Проверить отсутствие одного теста в списке, ненулевой выход Cargo и завершение с нулём тестов. В каждом случае ожидать ненулевой статус и путь к журналу. Подставные тесты runner не требуют новых Rust-фикстур. Форматирование, Clippy и полные тесты остаются обязательными для интеграции по [AGENTS.md](../../../../AGENTS.md#проверки-из-корня-workspace).

## Выпуск и обновление GPUI

### Сборка и проверка без окна

В чистом worktree записать исходный commit, версию GPUI, параметры машины и сборки, режим профиля Cargo и отдельный каталог артефактов. Перед выпуском и на обеих сторонах обновления повторить короткий набор и следующие команды:

```sh
cargo fmt --all -- --check
cargo clippy --locked --workspace --all-targets -- -D warnings
cargo clippy --locked -p workspace-desktop --features gpui-test --all-targets -- -D warnings
cargo test --locked --workspace
cargo test --locked --workspace --no-default-features
cargo test --locked -p workspace-desktop --features gpui-test --all-targets
cargo build --locked -p workspace-desktop --bin workspace-desktop \
  --example ui_gallery --example gpui_chat_probe --example gpui_macos_window_probe --example ui_scene
cargo build --locked -p workspace-desktop --no-default-features --bin workspace-auth
cargo run --locked -p workspace-desktop --example ui_scene -- --list
```

Эти команды используют обычный профиль Cargo, как в GPUI-21. Если выпускаемый пакет собирается с `--release`, подставить именно бинарник этого профиля в последующих шагах и повторить проверки его экземпляра. Ожидается отсутствие Iced в дереве рабочих зависимостей `cargo tree --locked --workspace -e no-dev`. В `workspace-auth --help` должна быть команда `sync`. Запустить `status` и `sync` с заведомо пустым `WORKSPACE_AUTH_STATE_DIR`: `status` завершается успешно, `sync` возвращает ошибку отсутствия аккаунтов, оба сообщают `No saved Workspace accounts.`. Это проверка headless CLI без обращения к Keychain и стенду.

Передать копию проверяемого бинарника в отдельной папке в `sh scripts/bundle-workspace-desktop-macos.sh "$binary"`. Проверить `codesign --verify --strict "$app"`, Mach-O архитектуру, `CFBundleExecutable=workspace-desktop`, `CFBundleIdentifier=com.exordos.workspace-desktop` и соответствие содержимого пакета конкретному SHA. Подпись из script локальная, ad hoc. Если готовится дистрибутив с другой подписью, запускать проверку на экземпляре с итоговой подписью.

### Окно и выделенный стенд

- **Нативная проверка без живых данных.** В интерактивной сессии запустить текущий `gpui_macos_window_probe`. Проверить изменение счётчика пробелом, скрытие красной кнопкой, восстановление из меню Workspace того же окна, сохранение фокуса и завершение. При повторе с `WORKSPACE_DESKTOP_DISABLE_TRAY=1` красная кнопка штатно завершает процесс. `gpui_chat_probe -- --reproduce-scroll-jump` воспроизводит нагрузочную прокрутку на фиксированных данных со своим `op_id`. Для рабочей истории, клавиатуры и редактора применить сценарий UI-12, если его сохранённые артефакты доступны, либо собрать предсказуемое воспроизведение на том же синтетическом маршруте. Проверить Tab/Shift+Tab, Escape, Page Up/End, фокус после сворачивания, ввод, вставку и переносы на 1440 и 700 логических px. Зафиксировать фактический размер и масштаб окна.
- **Штатный пакет.** Запустить через `open --env "WORKSPACE_AUTH_STATE_DIR=$isolated_profile" --env WORKSPACE_DESKTOP_DEBUG=1 "$app"` в отдельной папке профиля. Без тестовых аккаунтов проверить запуск, скрытие и восстановление окна, выход и `event=workspace_shutdown_finished result=clean`. Записать путь пакета, PID и системный номер окна до и после восстановления. Следующее окно запускать после завершения предыдущего процесса. Синтетические пробы, пакет с пустым профилем и полноценный стенд дают разные наблюдения.
- **Выделенный Workspace при выпуске или смене GPUI.** Использовать тот же проверяемый пакет и отдельный профиль A/B, секреты через штатный вход CLI. Выполнить шаги [баннера macOS](../../modules/shell-platform.md#клик-по-баннеру-macos) и [жизненного цикла окна](../../modules/shell-platform.md#жизненный-цикл-окна-из-строки-меню-macos). В одном экземпляре приложения убедиться в приросте счётчика B, системном баннере и фокусировке точного сообщения при клике из открытого и свёрнутого состояния. Через второй клиент подтвердить ответ одной доставкой. При восстановлении сети проверить сходимость истории, сводок и курсора без дублей, затем вернуть окно и завершить процесс штатно. Записывать только псевдонимы A/B, наблюдения, технические ID и `op_id`. Доступ к Keychain, уведомлениям и выделенному стенду нужен этому прогону. Когда такой доступ недоступен, указать блокер и оставить приёмку стенда открытой.

### Сопоставление двух версий

1. Снять базу на предыдущем принятом SHA до правки зависимости. При сравнении выбирать максимально близкие коммиты с теми же сценариями и нагрузочными данными. Зафиксировать версию, Cargo features и lockfile в корне обоих worktree. В кандидате изменить точную версию GPUI в `crates/workspace-desktop/Cargo.toml`, обновить `Cargo.lock` и проверить diff зависимостей. Для отдельной галереи Storybook также проверить прямые пины и lockfile по [UI-03](../gpui-ui-parity-storybook.md), если она участвует в обновлении. UI-17 закрепляет процедуру на `0.2.2`. Смена версии идёт отдельным изменением.
2. Выполнить одинаковые прогоны на обоих SHA и одной машине, без общего Cargo target, с одинаковыми Rust, профилем сборки, дисплеем, темой, языком, логическим размером и масштабом. Провести два независимых запуска [нагрузочного теста UI-11](../gpui-ui-parity-stability.md#запуск-и-замеры) для каждого SHA. Сравнить UUID и координату опоры, зазор у хвоста, порядок 64 клавиш и пяти переносов, медиану и максимум CPU-подготовки кадра и пиковый RSS. Допуск опоры — 1 логический px, хвост — 0 после вычета отступа. Изменение ресурсов сопоставить с разбросом повторов. Заметный выход за него повторить и объяснить данными, отдельно записать условия измерения. Измерение CPU не включает GPU и время представления кадра.
3. Сверить видимые отличия по доступным ручным кадрам. При уже выданном Screen Recording можно запустить существующую сцену `cargo run --locked -p workspace-desktop --example ui_scene -- chat-row light 700x600 "$out/scene"`. Каталог сцены создаёт сам пример. Метаданные `run.json` подтверждают размер, масштаб, SHA и границы. Опциональный `--verify` даёт `diff.json` и `diff.png` для повтора внутри одного запуска и намеренного сдвига. Кадры разных SHA сопоставить вручную. При отсутствии разрешения зафиксировать причину и выполнить проверку окна без захвата. Свою библиотеку сравнения в UI-17 не добавлять.
4. Повторить [клавиатурную приёмку UI-10](../gpui-ui-parity-accessibility.md). На GPUI 0.2.2 AX показывает системную рамку и кнопки AppKit, внутренние контролы не представлены VoiceOver, масштабирование содержимого отсутствует. Локальный AX-отчёт возможен с ранее разрешённым помощником. При обновлении расхождение с этим результатом записать отдельно от проверки клавиатуры. Если помощник недоступен, оставить AX непроверенным.

## Артефакты и критерии приёмки

| Источник | Как воспроизвести и где смотреть |
| --- | --- |
| Чистый checkout | Короткий набор, полный Cargo-прогон, сборки, CLI, подпись и список сцен воспроизводятся командами выше. Нативные примеры окна, прокрутки, галереи и ChatRow входят в Git. |
| Ранее снятая нативная UI-12 | В журнале рядом с репозиторием лежат `ui-12/native-accepted.patch`, `ui-10/read-ax.swift`, `ui-12/acceptance.l04eMOls/run.log` и `frames/{result.json,ui12-route.evidence.json}` в том же каталоге. Нативный запуск был на `1710e63` с патчем, `fafcd63` отличается тестом и Markdown. Перед повтором в отдельном worktree проверить `git apply --check`, собрать AX-помощник через `swiftc`, передать его путь через `WORKSPACE_UI10_AX_HELPER` и запустить `cargo run --locked -p workspace-desktop --example ui_scene -- --ui05-native <новая-папка>`. Требуются сохранённый патч и разрешения соответствующих нативных шагов. Ожидать `Ok/Clean` и запись маршрута. |
| Точное подтверждение обмена | Loopback выбрал личку и явную тему, подтвердил один POST/UUID через реальные локальные HTTPS/WSS и SQLite. Нативный Client UI-12 подтвердил ввод и постановку через синтетические источники. Пакет GPUI-21 на `70fd3c0` подтвердил стенд, настоящий баннер, ответ и reconnect. Итоговое подтверждение нового выпуска требует отдельного прогона кандидата. |

В новом каталоге прогона сохранить SHA, версии и окружение, журнал по каждому случаю и сводку с результатом. При скачке истории писать `op_id`, UUID и координаты опоры, число строк и поправку по [архитектуре](../../workspace-desktop-architecture.md#диагностические-журналы). Хранить кадры только при доступном захвате. Каждое значимое отличие при обновлении связать с шагом, журналом или кадром и указать, требуется ли исправление. Если локальные артефакты прежней приёмки недоступны, воспроизводимые проверки Git остаются самостоятельными, а точные повторения прошлых нативных сценариев помечаются в сводке с причиной.
