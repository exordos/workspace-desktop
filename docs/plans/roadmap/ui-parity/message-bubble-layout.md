# Общая ширина и раскладка бабла сообщения

## Основание

- Референс Workspace UI: commit `af0999886daaffefc2a7be33f8dcf3f484a0e9c1`, [общий bubble renderer](../../../../../workspace_ui/packages/web/src/widgets/workspace-message-list/workspace-message-bubble-presentation.ui.tsx). Базовый стиль обычного сообщения задаёт `max-w-[88%]` (строки 82–87); для quick actions фактический предел дополнительно учитывает `calc(100% - 3rem)` (строки 794–804). Входящие, исходящие и компактные варианты используют общий предел.
- Desktop на момент начала проектирования: `HEAD` `6336b4fdde46e59958d58f4751d9e7f3f972924a`. Рабочее дерево уже содержало посторонние незакоммиченные изменения. Текущая реализация общего предела 88% внесена после этой исходной ревизии.
- Точка общего оформления Desktop — `MessageBubble` в `crates/workspace-desktop/src/gpui_client/ui/content.rs`; общий предел 88% внесён. До этой реализации `surface` задавал фиксированный `MESSAGE_BUBBLE_MAX_WIDTH = 680 pt` из `ui/theme.rs`; та же константа участвует в отдельных ограничениях медиа (`history/media_album.rs`). Строка истории резервирует 40 pt под аватар и 8 pt зазора у входящих и может резервировать 20 pt у внутреннего угла для реакций (`history/viewport.rs`).

## Контракт раскладки

1. Общий предел стандартного бабла — 88% **доступного слота строки сообщения**. Слот измеряется после вычета элементов строки, которые не являются баблом: аватара и зазора входящего сообщения, а также резерва у угла, если он нужен для быстрых действий. Входящие остаются слева, исходящие справа. У общей композиции нет отдельного предела в pt: на широких и ультрашироких окнах 88% рассчитываются от актуального слота.
2. Общий предел задаёт рамку для содержимого, а само содержимое может иметь собственные ограничения. Не добавлять к общему пределу ещё один фиксированный cap 680 pt. Одиночное изображение, видеопревью, альбом и внутренние карточки сохраняют свои естественные ограничения по пропорциям, высоте и типу контента; их размер не может вынести бабл за 88% слота. Для каждого специального типа сверять его отдельный контракт с референсом и существующим владельцем поведения. Poll не считать обычным баблом автоматически: до включения в общий контракт проверить его отдельную композицию и размеры в согласованном референсе.
3. Внутренние отступы пузыря сохраняются. Длинный текст переносится по доступной ширине; содержимое с собственным поведением переноса или прокрутки (например, код и длинные ссылки) остаётся внутри рамки бабла, не распирает строку и не теряет читаемые данные.
4. Для обычного текстового абзаца время и статус продолжают последний ряд как trailing inline-элемент. Если в последнем ряду не хватает места, этот элемент целиком переносится на следующий ряд внутри того же абзаца; он не вынимается в отдельный footer. В отдельный footer метаданные уходят для структурных блоков, к которым inline-вставка не подходит, и для специальной раскладки с реакциями/карточками. Время поверх медиа остаётся на контрастной подложке в углу, если это предусмотрено типом содержимого; время звонка сверяется с отдельной карточкой звонка.
5. При изменении ширины строки пересчитываются ширина и высота затронутых баблов и внутренних карточек в пределах их собственных ограничений. Список сохраняет видимую опорную строку и положение у хвоста по существующему контракту `Viewport`; кэш обычных текстовых баблов не должен возвращать геометрию предыдущей ширины.
6. Быстрые действия не меняют геометрию бабла. Их зона размещается в зарезервированном слоте и не заслоняет текст, время или статус; если для действий требуется внутренний резерв, он учитывается при расчёте доступного слота.

## Матрица приёмки

| Сценарий | Проверить |
| --- | --- |
| Обычный короткий текст; входящий и исходящий | Бабло сохраняет компактную ширину, правильное выравнивание и групповые углы. Короткое время может стоять в последней строке. |
| Длинный текст и rich text | На ширинах окна 320, 500, 760, 1440 и 3440 pt общий предел равен 88% доступного слота; ширина увеличивается вместе со слотом и не упирается в прежние 680 pt. Переносы, выделение, ссылки, упоминания и клик-зоны работают. |
| Длинный URL, непрерывная строка, кодовый блок | Контент остаётся внутри предела общего бабла. Проверить перенос либо внутреннюю прокрутку по принятому поведению конкретного блока; нет горизонтального распирания истории и обрезанного времени. |
| Время и статусы | Время и статус — trailing inline-элемент последнего текстового абзаца. При нехватке места весь элемент переносится на следующий ряд; для неподходящих структурных блоков и блока реакций используется footer. Проверить pending, sent, delivered, read, failed и неизвестную доставку без наложения. |
| Реакции и быстрые действия | Footer со структурными реакциями остаётся в бабле, метаданные не конкурируют с последним чипом. Наведение/фокус показывает быстрые действия без изменения ширины или скачка раскладки. |
| Цитата, пересылка, карточка звонка | Вложенные карточки не выходят за общий предел бабла, сохраняя собственные размеры; время/статус следуют структуре конкретной карточки. Для mixed quote + завершающий абзац проверено продолжение inline-tail в терминальном тексте; звонковую карточку не считать обычным текстовым абзацем. Остальные структурные сочетания проверять отдельно. |
| Фото, видео и альбом | Общая рамка остаётся в пределах 88%, а собственные ограничения превью и плиток (например, высота и пропорции) сохраняются и не заменяются вычислением ширины без cap. Подпись использует ширину рамки; время поверх медиа показывается только в предусмотренной для типа позиции и остаётся читаемым. |
| Poll | Проверить отдельную композицию и её собственные размеры по согласованному reference/контракту; не применять к ней утверждение об общем пределе обычного бабла до подтверждения владельца поведения. |
| Защищённое сообщение | Нераскрытый placeholder, запрос ключа, ошибка ключа и раскрытый rich text используют общий предел там, где они занимают стандартный bubble renderer. Проверены геометрия protected tail и отзыв доступа при отложенном замере. `ProtectedLayout` передаёт tail терминальному тексту, включая mixed quote + завершающий абзац; защищённые ссылки сохраняют исходные диапазоны. Проверить несколько фрагментов и структурные окончания отдельно; общий паритет защищённых сценариев не подтверждён. |
| Смена ширины и ultrawide | Изменить ширину окна в обе стороны при сообщениях выше и ниже видимой опоры; высоты обновляются, опорное сообщение не прыгает. На 3440 pt бабло следует 88% доступного слота, а не фиксированному лимиту. |

## Текущий статус и незавершённые проверки

- Общий предел 88% и inline-tail внесены для обычного/interactive текста, завершающей подписи к медиа, protected fallback и терминального текста `ProtectedLayout`; смешанный сценарий quote + завершающий абзац подключён к tail. Исходная ревизия до этих незакоммиченных правок — `HEAD` `6336b4fdde46e59958d58f4751d9e7f3f972924a`; текущая реализация проверялась как рабочее дерево поверх него.
- Исполнитель подтвердил 5/5 целевых проверок: радиус/геометрия, mixed layout, protected geometry и отзыв доступа, selection цитаты, координаты. `cargo check-architecture` и `cargo check -p workspace-desktop --lib` прошли.
- Полный `cargo fmt --all -- --check` и all-targets проверка не подтверждены как успешные: отмечены проблемы форматирования/окружения; all-targets также встретил ошибки sandbox bind, unrelated selector и пример с Tray API. Они не являются доказательством прохождения полного набора.
- Структурные окончания, другие сочетания блоков и protected layout с несколькими фрагментами остаются неподтверждёнными; не заявлять для них полный паритет. Нативная визуальная приёмка пользователем не проведена.
- Не подтверждены реальные размеры и положение времени при переносах и resize, selection/hit indices во всех вариантах rich text, структурные footer-сценарии, ultrawide, медиа и сохранение опоры истории. Матрица выше остаётся планом приёмки для этих случаев.
