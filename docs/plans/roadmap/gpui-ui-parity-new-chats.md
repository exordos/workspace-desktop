# Новые чаты и каналы в Workspace Desktop

[UI-паритет](gpui-ui-parity.md#очередь-задач) · [Сценарии мессенджера](messenger-next.md#расширение-мессенджера) · [Личный чат и создание канала](../features/messenger/conversations.md#разговоры) · [Поиск людей](../features/foundation/directory.md#dir-002)

## Результат итерации

Плюсик переключает левый сайдбар в режим «Новые чаты и каналы». Стрелка «Назад» возвращает пользователя в прежнюю папку с её позицией и открытым разговором. Сверху два действия — «Начать чат» и «Создать канал». Блок «Каналы» ниже содержит четыре фильтра в порядке, согласованном для Desktop.

| Фильтр | Что показывает |
| --- | --- |
| С подпиской | Активные каналы, где у пользователя есть членство. |
| Без подписки | Доступные для обнаружения активные каналы, где у пользователя нет членства. Состав и разрешённые действия определяет сервер. |
| Все | Активные каналы и лички текущего аккаунта. Архив исключён. |
| Архив | Архивные каналы и лички текущего аккаунта. Строка открывает историю, отдельное действие восстанавливает разговор по правам. |

«Начать чат» открывает поиск коллеги с одиночным выбором. Клик по человеку открывает существующую личку или создаёт её и открывает обычный редактор. «Создать канал» открывает модалку названия и необязательного описания. После подтверждения создания показываем модалку выбора участников. Можно выбрать нескольких людей, подтвердить добавление или пропустить шаг. После добавления или пропуска открываем созданный канал.

## Референс и решения

- **Figma.** Опорные кадры — [левый сайдбар «Начать новый чат»](https://www.figma.com/design/VmfwiIV4fW8gHfU3AhCZGZ/Exordos-Core--Copy-?node-id=2473-8555), [«Создать канал»](https://www.figma.com/design/VmfwiIV4fW8gHfU3AhCZGZ/Exordos-Core--Copy-?node-id=4284-21364), [«Добавить участников» после создания канала](https://www.figma.com/design/VmfwiIV4fW8gHfU3AhCZGZ/Exordos-Core--Copy-?node-id=4284-22074). Фрейм диалога в макете шириной 351 px. Высоту подбираем по содержимому и доступной высоте окна.
- **Desktop.** Пункт «Создать групповой чат» исключён из панели. Для лички берём поиск и строки человека из подбора участников и открываем результат сразу после выбора. «Архив» размещаем последним фильтром нижнего блока, «Все» включает лички и каналы без архива. В первом срезе формы канала используем поля макета. Настройки канала и приглашение по ссылке требуют собственных сценариев.
- **Workspace Electron.** На `e44f14f2` плюсик открывает модалку с личкой, каналом, темой и архивом. Поведение лички и архива переносим в новую компоновку. В форме Electron участники выбираются до подтверждения. Запрос создания стрима и добавление участников выполняются по отдельности, поэтому GPUI может показать их в двух последовательных модалках. [Точка входа](../../../../workspace_ui/packages/web/src/widgets/sidebar/sidebar-workspace.ui.tsx) · [Форма](../../../../workspace_ui/packages/web/src/features/create-chat/create-chat-dialog.ui.tsx) · [Операции](../../../../workspace_ui/packages/web/src/entities/messenger/messenger-create-chat-actions.lib.ts)

## Владельцы данных и команд

- **Core.** Справочник отдаёт пользователей текущего проекта из `GET /users/`. Мессенджер владеет каталогом, типом стрима, правами, созданием и членством. Личный стрим использует `direct_user_uuid`, общий создаётся без этого поля. Штатный каталог Desktop сейчас отфильтровывает `is_archived` до сборки снимка. Для архива нужен исходный серверный признак в отдельном представлении панели, с сохранением правил активного каталога. [API Workspace `bc986e0`](../../../../workspace_backend/docs/ru/workspace_api.md) · [Каталог Desktop](../../../crates/workspace-core/src/messenger/catalog.rs)
- **Desktop.** Сайдбар владеет своим режимом, фильтром и поиском. Команды идут через Runtime с выбранной сессией, а результат открытия разговора использует штатный маршрут. При смене аккаунта закрываем формы и снимаем старый выбор. Просроченный ответ не открывает чат в новом аккаунте.
- **Каналы без подписки.** `GET /messenger/streams/` отдаёт потоки видимые текущему пользователю, а вкладка каталога каналов в Electron отключена. Нужен контракт источника разрешённых к обнаружению каналов и признака членства. До его подтверждения UI проверяем на фикстуре. Если источника на сервере нет, показываем явное состояние недоступности и выделяем серверную задачу. Пустой результат показываем после успешного запроса с нулём строк. [Контракт каталога](../features/messenger/conversations.md#msg-chat-012) · [Текущий Electron](../../../../workspace_ui/packages/web/src/features/create-chat/create-chat-dialog.hook.ts)

## Приёмка и точка продолжения

Справочник, команды создания и проверку источника «Без подписки» можно готовить независимо от отрисовки. После технической проверки UI на фиксированных данных показать отдельные превью компонентов и снимки экранов, затем сразу продолжить подключение к штатным командам. Просмотр пользователем проходит в следующем раунде. Замечания по внешнему виду вносить точечно в компоненты и экраны, сохраняя согласованные сценарии. [Правила тестирования](../../../skills/workspace-desktop-testing/SKILL.md)

- **Core.** Проверить разделение активных и архивных стримов, видимость при отсутствии членства, повтор создания и частичный результат при добавлении участников.
- **GPUI loopback.** Пройти от плюсика до отправки первого сообщения, создания канала и добавления участников, затем проверить фильтры и восстановление из архива. При смене аккаунта во время запроса история и результаты остаются в своих контекстах.
- **Выделенный Workspace.** С двух аккаунтов подтвердить доставку первого сообщения, появление канала у участника и доступность архива. Отдельно записать результат проверки источника каналов без подписки.

План подготовлен по Desktop `main` на `88bba07` с текущими локальными изменениями. Реализация и проверки запуска относятся к задачам из таблиц. Следующий шаг — взять общие компоненты UI-19.1–3 и собрать на них экраны с фиксированными данными.
