# UI-03. История ChatRow и снимки GPUI

Сцена `chat-row` показывает рабочий [ChatRow](../../../crates/workspace-desktop/src/gpui_client/ui/content.rs) из каталога. Для длинного названия канала, последнего сообщения и счётчика используются [данные UI-02](gpui-ui-parity-fixtures/scenes.json). Исходный вариант — выбранная строка с инициалами вместо фотографии и счётчиком 3. Клик или Enter на строке выбирает её. В Storybook можно менять название, выбор, видимость счётчика и палитру Blue Mist.

## Открыть историю

Из корня Workspace Desktop в графической сессии macOS:

```sh
cargo run --locked --manifest-path crates/workspace-desktop/examples/ui_storybook/Cargo.toml -- chat-row
```

`--list` вместо ID выводит название и описание без окна. У этой цели разработки свой lockfile. Версия Storybook 0.5.0 и её часть `gpui-storybook-core` отозваны в crates.io. Сборка использует контрольные суммы опубликованных архивов и версии отозванных зависимостей из lockfile публикации. Макросы регистрации отключены: их зависимость GPUI для host требует отдельной сборки Metal без `runtime_shaders`. История регистрируется через `StoryContainer::panel` и выбирается по `chat-row` через входной параметр `Gallery::view`. Проверить дерево зависимостей и кнопки истории можно без нативного окна:

```sh
cargo tree --locked --manifest-path crates/workspace-desktop/examples/ui_storybook/Cargo.toml -i gpui
cargo test --locked --manifest-path crates/workspace-desktop/examples/ui_storybook/Cargo.toml
```

## Снять и сравнить кадры

У Storybook 0.5.0 есть API открытия истории в галерее. Для управляемой области содержимого, ожидания кадра и сохранения файлов запускай ту же строку отдельной командой. Укажи свободный каталог вывода. Запускай через `cargo run` из чистого checkout, чтобы SHA в метаданных соответствовал исходникам бинарника.

```sh
cargo run --locked -p workspace-desktop --example ui_scene -- chat-row light 700x600 /private/tmp/workspace-chat-row-v1
cargo run --locked -p workspace-desktop --example ui_scene -- chat-row light 700x600 /private/tmp/workspace-chat-row-check --verify
```

`dark` задаёт тёмную версию, `--list` выводит список сцен. Команда проверяет существующее разрешение macOS на запись экрана без запроса и сохраняет только номер собственного окна из AppKit. В новом каталоге `chat-row-<SHA>-baseline` появятся `frame.png` и `run.json`. JSON хранит тему, фактический размер содержимого, масштаб, физический размер PNG, размер кадра до обрезки симметричного системного канта с прозрачной кромкой, число снятых пикселей, номер окна, положение и размер строки. Если окно не отрисовало ChatRow за 5 секунд, ошибка укажет ID и шаг. Для сравнения используй один дисплей и одинаковый масштаб. Например, Retina может дать PNG 1400 × 1200 для логического размера 700 × 600. Кадры UI-02 Electron сняты с DPR 1, при сопоставлении приводи их к одному масштабу.

`--verify` сохраняет в том же окне исходный кадр, повтор с теми же параметрами и третий кадр со сдвигом контейнера на 12 логических px вправо. `diff.json` содержит измерения и область изменений. `diff.png` выделяет изменившиеся пиксели. Команда проходит, когда повтор совпадает по пикселям и геометрии, а отличия контроля попадают в полосу исходной и сдвинутой строки. Сдвиг задаёт только демонстрационная сцена.

Полную компоновку рабочего окна описывают [сценарии UI-02](gpui-ui-parity-fixtures/README.md). Этот кадр проверяет отдельный компонент.
