# UI-11. Длинная история и ввод под нагрузкой

Сценарий открывает рабочий экран разговора с 600 разновысокими сообщениями. Затем подгружает 50 старых строк, сужает область разговора с 1061 до 340 px, увеличивает редактор переводами строки, меняет высоту строки над опорой и добавляет сообщение снизу. После перехода «К последним» приходит ещё одно сообщение. Источник отвечает фиксированными снимками. Поздний размер изображения представлен ростом синтетической строки, а подключение вложений описано в UI-15.

В тесте проходят обычные обработчики страницы, изменений истории, рисования и ввода. Проверяются UUID опоры и её координата относительно области прокрутки с допуском 1 логический px. У хвоста проверяются новый UUID и отступ до нижнего края за вычетом 12 px внутреннего поля списка. В редактор должны попасть ровно 64 печатные клавиши и пять переводов строки в заданном порядке.

## Запуск и замеры

```sh
cargo test --locked -p workspace-desktop --features gpui-test --lib \
  long_history_keeps_reading_position_and_input -- --nocapture
```

Для замера RSS запускай один и тот же тестовый бинарник в двух отдельных процессах. При параллельных worktree используй отдельный Cargo target и проверь, из какого каталога собран пакет.

```sh
export CARGO_INCREMENTAL=0 CARGO_PROFILE_DEV_DEBUG=0 CARGO_PROFILE_TEST_DEBUG=0
cargo test --locked -p workspace-desktop --features gpui-test --lib \
  --no-run --message-format=json > /tmp/ui11-build.json
test_bin="$(python3 -c 'import sys,json; print(next(v["executable"] for v in map(json.loads,sys.stdin) if v.get("executable") and v.get("target",{}).get("name")=="workspace_desktop" and v["profile"]["test"]))' < /tmp/ui11-build.json)"
for repeat in 1 2; do
  /usr/bin/time -l "$test_bin" long_history_keeps_reading_position_and_input \
    --nocapture --test-threads=1 > "/tmp/ui11-bench-$repeat.log" 2>&1
done
```

Связывай запрос и измерение по `op_id`. Запись `anchor_measured mode=reading` содержит UUID, число строк, координаты и дельту. Для `mode=follow_end` ожидается новый UUID и нулевой зазор после учёта внутреннего поля. `cpu_draw_us` измеряет подготовку одного кадра библиотекой GPUI на CPU в тестовом окне. `maximum resident set size` от `time -l` содержит пиковый RSS процесса в байтах. Объём видеопамяти и время представления кадра на экране этим тестом не измеряются.

Базовые повторы на Mac15,6, macOS 27.0.1 (26A434), arm64, Rust 1.100.0 и GPUI 0.2.2:

| Повтор | Опора в логических px | Зазор у хвоста | Ввод | CPU кадр, медиана / максимум | Пиковый RSS |
| --- | --- | --- | --- | --- | --- |
| 1 | −5 → −5 на пяти шагах | 0 px | 64 + 5 событий | 1271 / 1898 мкс | 23 658 496 Б |
| 2 | −5 → −5 на пяти шагах | 0 px | 64 + 5 событий | 1198 / 1733 мкс | 23 560 192 Б |

Параметры окружения и исходные журналы `bench-1.log`, `bench-2.log` лежат в папке `ui-11` рядом с журналом миграции. Повторы задают исходную точку для сравнения на той же машине.

## Один прогон macOS

Для приёмки на реальном окне применяется синтетический Client из UI-06–08. Наложение `ui-11/native-ui11.patch` продолжает сценарий в том же окне после проверок меню. Оно открывает рабочую личку с нагрузочной историей, подаёт клавиши через GPUI с паузой 12 мс, сужает нативное окно до 700 × 600 и сохраняет кадр `ui11-tail-700.png`. Журнал `ui11_native` связывает координаты и интервалы между вызовами отрисовки с `op_id`. Результаты нативной приёмки хранятся в журнале миграции.

Из отдельного worktree с кодом UI-11:

```sh
gate=/private/tmp/workspace-desktop-gpui-gates
git apply "$gate/ui-06-08/native-verified.patch"
git apply "$gate/ui-11/native-ui11.patch"
out="$(mktemp -d "$gate/ui-11/native.XXXXXXXX")"
cargo run --locked -p workspace-desktop --example ui_scene -- \
  --ui05-native "$out/frames" > "$out/run.log" 2>&1
cat "$out/frames/result.json"
```

[Отдельный прототип GPUI](gpui-probe.md#воспроизвести-скачок-истории-при-догрузке-сверху) может отрисовать и поздно увеличить размер своего синтетического изображения. Рабочий нагрузочный сценарий использует тот же viewport и редактор, что и клиент, и проверяет аналогичное изменение высоты без сети.
